# Fase 12E — Roles + auditoría administrativa

Cambios implementados de forma conservadora:

1. Se agregó `src/utils/authAdmin.js` para centralizar roles y permisos.
2. Se reconocen roles desde `user_metadata.rol`, `user_metadata.role`, `app_metadata.rol` o `app_metadata.role`.
3. Roles contemplados:
   - `admin`: acceso completo.
   - `caja`: pedidos y generador.
   - `cocina`: pedidos.
   - `mesero`: pedidos.
4. Si un usuario no tiene rol configurado, por seguridad operativa queda como `admin` para no bloquear el sistema actual.
5. Se muestra el rol activo en el panel administrativo.
6. Se ocultan pestañas no permitidas según el rol.
7. Se protege eliminación de pedidos por permiso de rol y se mantiene la clave local adicional como respaldo de seguridad.
8. Se registra auditoría no bloqueante en la tabla `auditoria_pedidos` para:
   - pedido entregado / pendiente
   - finalización masiva
   - pedido borrado
9. La auditoría es silenciosa: si la tabla no existe todavía, la app sigue funcionando y solo muestra advertencia en consola.
10. No se tocó cliente, mesas, WhatsApp, cálculos ni la lógica de creación de pedidos.

## Tabla opcional recomendada en Supabase

```sql
create table if not exists public.auditoria_pedidos (
  id bigint generated by default as identity primary key,
  pedido_id text null,
  codigo_pedido text null,
  accion text not null,
  detalle jsonb null,
  usuario_email text null,
  usuario_rol text null,
  actor text null,
  created_at timestamptz not null default now()
);
```

## Cómo asignar rol a un usuario

En Supabase > Authentication > Users > seleccionar usuario > User Metadata:

```json
{
  "rol": "admin"
}
```

Roles posibles: `admin`, `caja`, `cocina`, `mesero`.
